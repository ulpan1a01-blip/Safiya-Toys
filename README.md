# Safiya-Toys

Полноценный локальный интернет-магазин с розничными и оптовыми покупками: Node.js 24+, Express 5, встроенный SQLite (`node:sqlite`), HTML/CSS и JavaScript без сборки. Исходные логотипы и иконки из задания сохранены без изменений в `public/assets/images`.

## Запуск

1. Установите Node.js **24 или новее**.
2. Распакуйте весь архив, откройте терминал в папке `Safiya-Toys-full`.
3. Выполните `npm install`, затем `npm start`.
4. Откройте **http://localhost:3000**. Не открывайте HTML двойным щелчком: нужен сервер.

Если порт занят: `PORT=3001 npm start` (macOS/Linux) или `$env:PORT=3001; npm start` (PowerShell).

## Публикация на Render

В проект добавлен `render.yaml`. Загрузите файлы в GitHub, затем в Render выберите **New → Blueprint** и подключите репозиторий. Конфигурация сама задаст сборку, запуск, HTTPS-cookie и доступ из интернета.

На бесплатном тарифе Render база SQLite и загруженные фото могут сбрасываться при повторном развёртывании. Для учебной демонстрации этого достаточно. Для реального магазина подключите постоянный диск и задайте `DATA_DIR` и `UPLOAD_DIR` как папки на этом диске.

## Тестовые аккаунты

| Кабинет | Email |
|---|---|
| Покупатель | customer@safiya.test |
| Продавец | seller@safiya.test |
| Курьер | courier@safiya.test |

Пароль не хранится в открытом коде. Перед первым запуском задайте переменную среды `SEED_PASSWORD` длиной не менее 12 символов. Она задаёт начальный пароль для трёх ролей.

Вход находится в профиле. Роль определяется сервером автоматически. Самостоятельная регистрация создаёт только покупателя. Для одновременной проверки ролей используйте разные профили браузера или приватные окна: сессия общая для вкладок одного профиля.

## Проверка сценария

1. Покупатель: выберите игрушку, нажмите «В розницу» или «Оптом», добавьте товар в корзину и оформите заказ. Для опта автоматически применяется минимальное количество продавца.
2. Продавец: «Заказы» → назначить Армана; либо перевести в обработку и разрешить свободное принятие.
3. Курьер: принять доступный заказ или открыть назначенную доставку → «В пути» → «Доставлен».
4. Статусы обновляются в открытых кабинетах через Server-Sent Events без перезагрузки. Покупатель видит историю в профиле.
5. Продавец: «Товары» → добавление/редактирование → укажите категорию, розничную цену, оптовую цену и минимальное количество для опта. Там же можно выбрать несколько фото.

`npm test` выполняет интеграционные проверки с отдельной временной базой, включая вход трёх ролей, запреты доступа, регистрацию, загрузку фото, склад, корзину, избранное, полный цикл доставки, отмену и сохранность после перезапуска. Рабочая база не меняется тестами.

## Структура

- `frontend/` — HTML, дизайн-система CSS, интерфейс кабинетов и обёртка API.
- `backend/db.js` — схема SQLite, подготовленные запросы, начальные записи, хеширование.
- `backend/server.js` — Express API, сессии, роли, загрузки и бизнес-правила.
- `public/assets/images/` — неизменённые оригиналы бренда и референс.
- `public/assets/products/` — изображения игрушек, извлечённые из предоставленного референса; это изображения демонстрационных товаров, не отдельные фотографии высокого разрешения.
- `uploads/` — добавленные продавцом изображения (создаётся автоматически).
- `database/shop.sqlite` — постоянная база (создаётся при первом запуске).
- `tests/` — автоматические интеграционные проверки.
- `PROMPT_RU.txt` — исходное задание.

## API

Все изменяющие запросы требуют заголовок `X-Safiya-Request: 1`. Аутентификация — HttpOnly cookie, SameSite=Strict. Для JSON используйте Content-Type application/json.

| Метод и путь | Назначение / доступ |
|---|---|
| GET /api/auth/me | Текущая сессия |
| POST /api/auth/register, /login, /logout | Регистрация, вход, выход |
| GET /api/categories | Категории |
| GET /api/products | Товары; q, category, min, max, stock=1, sort=price_asc/price_desc |
| GET /api/products/:id | Товар |
| POST /api/products, PUT /api/products/:id | Продавец; multipart: name, price, wholesale_price, wholesale_min, stock, category_id, description, specs (JSON), kept (JSON), photos (до 8) |
| DELETE /api/products/:id | Продавец; скрытие товара без разрушения истории |
| GET /api/favorites | Избранное покупателя |
| PUT, DELETE /api/favorites/:id | Добавить/убрать избранное |
| GET /api/cart | Корзина покупателя |
| PUT /api/cart/:id | Установить quantity и purchase_type: retail/wholesale |
| DELETE /api/cart/:id | Удалить позицию |
| POST /api/orders | Оформить: name, phone, address, comment, payment |
| GET /api/orders | Заказы в пределах роли |
| PATCH /api/orders/:id | Продавец: status, courier_id, available |
| GET /api/deliveries | Курьер: свои и разрешённые доступные заказы |
| PATCH /api/deliveries/:id | Курьер: action = accept / travel / done / failed |
| GET /api/users | Продавец: клиенты и курьеры, занятость и заказы |
| PATCH /api/users/me | Изменить свои name, phone |
| GET /api/stats | Продавец: показатели и продажи по дням |
| GET /api/events | События обновления без персональных данных |

## Бизнес-правила и безопасность

Цены — целые тенге; отрицательные цена и остатки отклоняются на сервере. Оформление заказа выполняется в транзакции SQLite, цена берётся из базы, склад уменьшается атомарно. Отмена возвращает остаток один раз; закрытые заказы неизменяемы. Курьеру разрешена одна активная доставка. Неудавшаяся доставка возвращается продавцу в обработку без возврата товара на склад (заказ не отменяется).

Пароли хешируются scrypt с индивидуальной солью. Сессии сохраняются в базе в виде хешей случайных токенов. Ограничены попытки входа/регистрации. SQL параметризован, пользовательский текст экранируется, включён CSP. Фото проверяются по типу, сигнатуре и размеру (PNG/JPEG/WebP, 5 МБ), имена случайные. Скриптовые SVG не принимаются. Страницы `/seller` и `/courier` и API защищены серверной проверкой роли.

Это готовый **демонстрационный локальный проект**, не настроенный публичный магазин. Онлайн-оплата не подключена; доступны наличные и карта при получении. Перед реальным запуском замените тестовые аккаунты, условия, демонстрационные изображения и характеристики реальными; настройте HTTPS, резервное копирование SQLite и uploads, политику хранения данных. При HTTPS установите `COOKIE_SECURE=1`. По умолчанию сервер слушает только 127.0.0.1; `HOST=0.0.0.0` включайте осознанно для доступа из локальной сети. `DATA_DIR`, `UPLOAD_DIR` позволяют выбрать отдельные каталоги хранения.

В исходнике нет отдельных фото товаров: для сходства с макетом использованы фрагменты игрушек из референса. Их разрешение ограничено; новые качественные фото загружаются в кабинете продавца. Фирменные круглые иконки приоритетны над другими значками на макете. Шрифт использует локальный Nunito, если установлен, и округлые fallback-шрифты без внешней загрузки.
